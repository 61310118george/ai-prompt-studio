# 風險與限制

## 2026-09-25 提示詞工作台新增限制

- 精簡比例僅代表所選 tokenizer 的文字長度差；輸出品質、重試與帳單需獨立驗證。
- 內建兩種 tokenizer，不代表所有模型；未知模型使用明示粗估。
- 合成基準不能當成真實使用者平均節省比例，真人研究尚未進行。
- 既有 Agent catalog 最後查證日為 2026-07-19，本次未全面更新各平台規格。
- 一般提示詞匯出是整檔替換，先看 Diff、確認與備份；記憶編程仍使用區段管理。
- 當前 hash 檢查與 atomic replace 之間未採跨程序鎖，DB 記錄與檔案也不是同一原子交易；不宣稱完整並行寫入保證。
- 搬移的原專案維持原樣，本次成果在任務原工作區的副本；使用者需避免兩份原始碼混用。

本文件用來記錄畢業專題可能遇到的風險、限制與處理方式。

## 目前已知風險

### Agent 官方記憶規格持續變動

- 狀態：已降低
- 說明：Codex、Claude Code、Gemini CLI、OpenClaw 的檔名、作用域與記憶功能可能更新。
- 處理：使用版本化離線 catalog，保存來源網址與查證日期；不在執行時自動下載未驗證模板。

### Web UI 與原生檔案權限邊界

- 狀態：已處理第一版
- 說明：pywebview 會讓 JavaScript 呼叫 Python，若 API 沒有限制，可能寫入任意本機路徑。
- 處理：DesktopApi 只接受選定根目錄內的相對 `.md`，拒絕 path traversal 與外部 symlink，並重新編譯而非信任前端傳回整份內容。

### 檔案被其他工具同時修改

- 狀態：已處理第一版
- 說明：使用者產生預覽後，編輯器或 Agent 可能先修改同一檔案。
- 處理：套用時重新比對 SHA-256；不一致就拒絕覆蓋並要求重新預覽。

### pywebview 與打包相容性

- 狀態：待持續驗收
- 說明：macOS WebKit、PyObjC、PyInstaller 與檔案對話框需在實際 `.app` 中驗證。
- 處理：已驗證 Next App 可啟動、bridge 與內建規格可載入、四大導航可操作；檔案對話框與長時間真實專案操作仍列入人工驗收。舊 PySide6 App 與 legacy 入口繼續保留。

### 規則式整理能力被誤認為 AI

- 狀態：已降低
- 說明：本機 compiler 能穩定格式化，但不能像 LLM 一樣理解與摘要任意內容。
- 處理：UI 與文件明確說明能力邊界，以結構化欄位確保輸出品質。

### 官方規範變動或不同平台差異過大

- 狀態：已發現
- 說明：不同 AI 工具的提示詞、記憶或設定方式可能不同，而且會隨時間變動。若要宣稱支援 Codex、Claude 等平台，需要查官方文件並限制範圍。
- 初步處理：畢專初期不要承諾完整支援所有平台，先做通用的記憶與提示詞管理，再選少數平台做模板示範；模板需要記錄版本、來源與更新時間。

### 「AI 個人化管理系統」範圍容易擴張

- 狀態：已發現
- 說明：此題目可能擴張成 AI 平台、提示詞工程工具、知識庫、版本控制與多平台整合，範圍偏大。
- 初步處理：先定義最小可行版本，避免一次做完整平台。

### 題目過大

- 狀態：待評估
- 說明：畢業專題若功能過多、技術跨度太大，容易無法在期限內完成。
- 初步處理：每個題目都先定義最小可行版本。

### 技術選型過度複雜

- 狀態：待評估
- 說明：使用太多不熟悉的新技術可能讓時間花在環境與除錯，而不是成果本身。
- 初步處理：優先使用使用者熟悉或容易掌握的技術。

### UI/UX 參考工具與實作框架不一致

- 狀態：已發現
- 說明：`ui-ux-pro-max-skill` 提供設計系統與多平台 UI/UX 指引，但不是 Python 桌面 GUI 框架。若期待它直接產生 Python macOS App，可能會有落差。
- 初步處理：將它作為 UI/UX 設計參考與檢查清單，實作框架另行選擇。

### 第三方 Skill 安裝權限受限

- 狀態：已處理
- 說明：Codex 嘗試安裝 `nextlevelbuilder/ui-ux-pro-max-skill` 到全域 `~/.codex/skills` 時被 session policy 拒絕；使用者已改用 `uipro init --ai codex` 安裝到目前專案 `.codex/skills/`。
- 初步處理：已確認目前專案存在 `.codex/skills/ui-ux-pro-max/SKILL.md`，後續需要重啟 Codex 讓 skill metadata 正式載入。

### 需求不清

- 狀態：待評估
- 說明：如果目標使用者、核心問題與交付物不明確，後續容易反覆修改方向。
- 初步處理：先完成 `docs/project-brief.md` 與 `docs/requirements.md`。

### `.codex/` 目錄目前無法由 Codex 寫入

- 狀態：已發現
- 說明：目前工作區權限阻擋 Codex 建立 `.codex/` 目錄，因此 `.codex/config.toml` 與專案 Skill 尚無法放入官方預期位置。
- 初步處理：先建立可寫入的專案文件，並用範本記錄 `.codex/config.toml` 與 Skill 內容。

## 已知協作限制

### 主要實作人力集中在使用者

- 狀態：已發現
- 說明：雖然是小組專題，但核心規劃與實作主要由使用者與 Codex 完成，其他組員預期主要負責報告或輔助工作。
- 初步處理：系統範圍需以單一主要開發者可完成為基準；功能優先順序要保守，避免依賴多人並行開發。

### 學校與老師要求尚未確認

- 狀態：已發現
- 說明：目前尚不確定學校或指導老師對畢業專題的明確要求，例如文件格式、審查節點、技術限制、展示標準或評分重點。
- 初步處理：先按一般資訊管理系畢業專題標準規劃：可實作、可展示、可說明、可產出文件；待正式要求確認後再調整。

### 三個月內完成展示版的時程壓力

- 狀態：已發現
- 說明：使用者希望三個月內大致完成第一個可展示版本，因此不可把第一版設計成完整平台或多 AI 工具深度整合。
- 初步處理：採 MVP 優先策略，先完成本機單人使用、記憶管理、提示詞組合、版本差異與 AI 精簡功能。

### 投入時間不固定

- 狀態：已發現
- 說明：使用者有時間時會與 Codex 一起完成專題，但每週固定投入時數尚不明確。
- 初步處理：任務拆解要小，並維持 `docs/next-actions.md` 作為恢復工作脈絡的入口；每次工作都要留下明確下一步。

### 額外成本限制

- 狀態：已發現
- 說明：使用者希望盡量不要額外花錢，因此第一版不應依賴付費雲端服務、付費資料庫、付費部署或高額 AI API 用量。
- 初步處理：優先採用本機儲存、開源工具與可替換 API 設計；AI API 功能設計成可設定、可限制用量，並保留不使用 API 也能操作基本功能的模式。

### Sequel Ace 與 SQLite 不完全對應

- 狀態：已發現
- 說明：使用者熟悉 Sequel Ace，但 Sequel Ace 主要是 MySQL/MariaDB 工具；SQLite 更適合本機桌面 App，但不能直接等同於 Sequel Ace 的使用方式。
- 初步處理：第一版採 SQLite，並提供匯出 CSV/Excel 或搭配 SQLite viewer 查看資料；避免為了使用 Sequel Ace 而引入 MySQL 服務成本。
