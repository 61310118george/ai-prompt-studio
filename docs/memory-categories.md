# AI 記憶分類

本文件用來定義第一版系統要管理的 AI 記憶分類。分類目標是讓使用者能清楚知道 AI 目前「知道什麼」、這些內容「用在哪裡」，以及日後要修改時應該改哪一塊。

## 第一版分類

### 個人背景

用途：記錄使用者的基本身分與長期背景。

範例：

- 科系
- 年級
- 目前角色
- 長期目標
- 使用 AI 的主要情境

這類資料用來讓 AI 理解「使用者是誰」。

### 技術能力

用途：記錄使用者熟悉、不熟悉或正在學習的技術。

範例：

- 熟悉 Python
- 會 SQL、資料庫、Excel
- JavaScript、HTML/CSS 看得懂
- Git、AI API 有概念

這類資料用來讓 AI 在建議技術方案時，不要選擇超出使用者負擔太多的方案。

### 專案背景

用途：記錄某個專案本身的基本資訊。

範例：

- 專案名稱
- 專案目的
- 目標使用者
- 使用場景
- 專案目前階段

這類資料用來讓 AI 理解「目前正在做什麼專案」。

### 專案需求

用途：記錄專案必須完成、可以完成、暫不完成與明確不做的功能。

範例：

- 必須能管理 AI 記憶
- 必須能用 UI 查看記憶區塊
- 可以支援 AI API 精簡內容
- 暫不做多人協作

這類資料用來讓 AI 在實作時對齊功能範圍。

### 偏好與限制

用途：記錄使用者的偏好、限制與決策原則。

範例：

- 盡量不要額外花錢
- 優先本機使用
- 不想引入過多付費服務
- 三個月內完成展示版

這類資料用來讓 AI 在做選型與規劃時自動避開不符合條件的方案。

### 常用提示詞

用途：保存可重複使用的提示詞片段或模板。

範例：

- 程式碼 review 提示詞
- 文件整理提示詞
- UI 設計提示詞
- 畢專報告撰寫提示詞

這類資料用來減少重複撰寫提示詞的時間。

### AI 工具規則

用途：記錄不同 AI 工具或平台的使用規則與格式限制，並作為模板轉換功能的依據。

範例：

- Codex 的專案規則應放在 `AGENTS.md`
- Codex Skill 應放在 `.codex/skills/`
- 某些平台需要特定提示詞格式

這類資料用來協助使用者區分不同 AI 工具的設定邏輯。

在本專題中，AI 工具規則不只是記事內容，而是系統內建功能的一部分。系統應能根據使用者選擇的 AI 工具或使用情境，將同一組記憶內容轉換成對應模板。

UI 設計上，AI 工具規則不應作為前台主要記憶分類頁籤，而應放在「輸出/轉換」流程中。例如使用者在產生提示詞時選擇目標工具：Codex、通用 ChatGPT、Claude。

第一版支援：

- Codex 專案協作模板
- 通用 ChatGPT 對話模板
- Claude 文字協作模板

暫不承諾完整支援所有 AI 工具。每個工具的官方規則可能變動，因此模板需要版本、來源與更新時間。

### AI 個性設定

用途：記錄使用者希望 AI 以什麼風格、語氣與工作方式回應。

範例：

- 直接、務實、少廢話
- 使用繁體中文
- 優先提供可執行步驟
- 遇到不合理範圍時要直接指出
- 不要過度鼓勵或空泛稱讚

這類資料用來控制 AI 的溝通風格與協作方式。

### 決策紀錄

用途：記錄已做出的重要決定與理由。

範例：

- 使用 Python + PySide6
- 使用 SQLite
- 核心功能離線可用
- AI API 為可選功能

這類資料用來避免日後忘記為什麼做某個選擇。

### 風險與注意事項

用途：記錄可能影響專案完成的風險與限制。

範例：

- 題目容易過大
- 學校要求尚未確認
- 時間不固定
- API 成本限制

這類資料用來讓 AI 在規劃時主動避開高風險方向。

### 下一步任務

用途：記錄目前最需要做的下一個動作。

範例：

- 確認記憶分類
- 設計資料表
- 畫 UI wireframe
- 建立 PySide6 專案骨架

這類資料用來確保專案可以中斷後恢復，不會每次都重新開始。
