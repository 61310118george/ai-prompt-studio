# 介面調整與驗收紀錄

日期：2026-10-07。這次僅更新本機，不推送 Git。

## V1.1–V1.4：分組與閱讀層級

提示詞範本庫改為「建立新提示詞／內建範本／已儲存的提示詞」三張有邊界的區塊；範本與已儲存項目也各自使用卡片、標題、分類與輔助文字，避免內容混在一起。

專案的一覽表新增「AI 輸出項目」。路徑位於 `deliverables/` 或 `outputs/`，以及檔名包含企劃書、交付驗收、符合度、展示指南、第三方來源的 Markdown，會歸到這一類；核心記憶與技能檔案優先維持原有分類。

健檢左欄每個資料夾改為獨立卡片，選取檔案以側邊色條標示；右欄每個問題也改為獨立卡片，行號置中。設定頁移除與 API 區塊重複的「本機安全」卡片，保留實際需要的 API 設定與 Agent 規格。

## 左下狀態：版本與 AI API

左下固定顯示版本 **V1.4** 與 API 狀態。版本統一從 `web-preview/version.js` 讀取；每次 App 更新與重新打包時必須更新這個唯一版本值。

API 燈號以選用 Gemini API 的狀態為準：綠燈表示 API Key 與選定模型已通過不含提示詞內容的連線驗證；紅燈表示未設定或已清除 Key；橘燈表示 Key、模型、額度或網路驗證異常。分析請求失敗也會轉為橘燈，下一次分析成功會回到綠燈。Key 只保存在目前 macOS 使用者的 App Support 本機私有檔，不會進入 SQLite、專案檔或 `.app`。

## 健檢清單：資料夾與專案類型

需要確認的文件依目前選定專案中的資料夾分組，群組標題顯示「專案資料夾：專案名稱／相對資料夾」。每項只顯示檔案名稱；完整相對路徑可在停留提示中查看。右側使用有底色的專案類型標籤：核心記憶、專案提示詞、專案技能。待確認數量改為填滿中段的狀態列，「更新」改為「最後更新時間」。

## 編輯器：章節編輯與範本摘錄

左側提供快速編輯章節、新增章節（主題與內容兩個欄位），取消建議章節選單。全文編輯保留在進階摺疊區；右側直接顯示完整修改後 Markdown 草稿，差異另列在摺疊區。儲存仍需預覽與確認，尚未更新或加入的欄位會阻擋預覽，避免漏存。

「擷取專案重點到提示詞工作台」會帶入目前編輯草稿，加上最多七份核心記憶文件，每份摘錄最多 1,800 字元，合計最多 12,000 字元。保留來源與截斷提示，屬本機前段摘錄而非語意摘要。結果只進工作台草稿，不寫入來源文件、不自動儲存資料庫、不呼叫 AI；使用者確認後按儲存版本才成為自己的範本。已有工作台草稿時先詢問是否取代。

## 提示詞一覽表：檔案用途說明

每個檔名下新增簡短用途，維持原有表格、分組與查看按鈕。常見檔名使用固定用途提示，Agent 檔案參考規格，其他文件顯示 Markdown 標題；無法判定就提示查看內容，不使用 AI、不消耗 Token。這些是用途提示，不保證等同內容摘要。

標題擷取只讀前 8 KB，跳過 YAML 與程式碼區塊。用途最多 52 字元、畫面最多兩行，長檔名可換行；窄螢幕沿用單欄排版。新增標題解析測試及一覽表逐列說明驗證，Python 測試共 48 個。

## 後續追加：範本與選用 AI 分析

- 「新增」確認為建立空白草稿，改名「建立空白提示詞」，未儲存草稿會先詢問是否放棄。
- 範本庫整合內建與已儲存範本：帶入內建範本後可改標題；可建立群組，自己的範本可拖曳至任一群組。群組與位置保存在本機資料庫。
- 設定加入 Gemini API：模型可改、Key 以密碼欄輸入，保存於目前使用者的 App Support 本機私有檔，不寫入 SQLite、不回傳 Key 至狀態 API，也不包進 `.app`。
- 工作台每次確認才送出草稿與工具名稱，上限 20,000 字元。先用本機規則阻擋常見密鑰；規則無法識別所有機密，使用者仍須檢查。
- 固定 HTTPS 官方 endpoint，拒絕重新導向；35 秒 timeout、不自動重試、限制回應大小。AI 回應當純文字顯示，不執行 HTML 或指令；修改草稿後隱藏舊結果。
- 狀態明確區分已設定與已驗證。用量超限、模型不存在、權限及連線失敗都有提示，離線功能繼續可用。
- 免費 API 與月費不是同一種額度。Gemini 免費資料使用與計費提示在設定及每次確認中顯示；無 API Key 不影響任何離線功能。

新增接口：`get_cloud_settings()`、`configure_cloud_analysis({api_key, model})`、`configure_cloud_analysis({clear:true})`、`analyze_with_ai({content, tool, consent:true})`、`list_prompt_groups()`、`create_prompt_group()`、`move_prompt_to_group()`。新增 migration 4，為舊資料庫以 additive 方式建立群組表。

最新驗收：52 項 Python 測試；Web 原 28 組版面加範本套用／另存／空白草稿與瀏覽器金鑰阻擋；桌面以模擬傳輸測試啟用、取消送出、結果純文字、草稿失效及清除金鑰。未進行真實 API 呼叫，須使用者自行提供 Key 後確認帳號權限與額度。

研究：2026-10-07 查核 [Gemini 價格](https://ai.google.dev/gemini-api/docs/pricing)、[Key 用法](https://ai.google.dev/gemini-api/docs/generate-content/api-key)、[Groq 免費限額](https://console.groq.com/docs/rate-limits)。本版只實作 Gemini。

## 現在怎麼用

1. 提示詞工作台：建立、分類與保存可重複使用的提示詞。「已儲存的提示詞」存在 App 資料庫，不等於資料夾內的 Markdown。
2. 專案：選資料夾，在「提示詞一覽表」看核心記憶、專案提示詞、專案技能。一般 Markdown 不代表 Agent 會自動讀取。
3. 點預覽右上角「編輯」：可改全文，或挑章節修改；先預覽差異再確認儲存。核心記憶提供協作／限制章節，提示詞提供任務／輸出章節，技能提供情境／步驟／驗證章節。
4. 記憶健檢：選定專案後自動檢查 Markdown，左側選問題文件，右側查看行號與標記。可直接開啟同一個編輯器。

「專案提示詞」是一般文件的整理分類，包含 README 與需求等背景資料，不表示每個檔案都是可直接執行的 Prompt。

## 用量提示的邊界

大型成本區改為工具下拉選單及最低、低、高、最高的顏色提示。只根據目前提示詞與掃描文件的粗估長度判斷輸入負擔，不代表完成整個專案的總 Token。

模型建議依任務關鍵字提供參考，月費建議不保證提高多少可用次數。沒有連接帳號額度、重置時間或帳單；不能以此宣稱「一定夠用」。本機模型沒有雲端 Token 計費，但仍受記憶體與上下文長度限制。

規格來源（查證 2026-10-07）：[Codex 模型](https://learn.chatgpt.com/docs/models)、[Codex 方案](https://learn.chatgpt.com/docs/pricing)、[Claude Code 方案](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)、[Claude 模型與限制](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code)。實際可用模型以帳號選單為準。

## 健檢範圍與安全

偵測疑似密鑰／密碼、覆寫指令、索取系統提示、外傳資訊、危險外部指令、隱藏字元、重複段落／整檔及 TODO 等候選整理項目。

攻擊指標參考 [OWASP Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)。採本機規則，不會執行文件中的指令。引用資安教材也可能被標記；沒有命中不等於安全，「不必要」不能靠規則完全判定。健檢不自動刪除或改檔。

掃描上限 5,000 個 Markdown；跳過依賴、Git、建置目錄及 symlink。單檔 2 MB 上限，過大或無法解碼的檔案顯示警告。這不是整台電腦或所有檔案格式的防毒掃描。

寫入保留 SHA-256 外部修改檢查、備份、原子替換與歷史復原。技能 YAML frontmatter 不會被章節操作移除；全文修改仍由使用者確認。

## 後續固定採用的版面流程

沿用 CSS 顏色變數、卡片樣式與響應式 Grid。欄位使用可縮小的網格、長路徑折行；窄螢幕切為單欄，彈窗限制在視窗內並可捲動。Web 與 App 共用同一份 HTML／CSS／JS，避免兩套畫面不同步。

每次改版都必須：跑功能測試 → 跑各寬度四分頁與彈窗 → 檢查水平溢出與 JavaScript 錯誤 → 人工查看截圖 → 跑桌面真實檔案操作 → 打包自我測試。自動 overflow 檢查不能取代人工檢視遮擋或可讀性。

本次通過：

- Python 30 個測試，包含核心／一般／技能編輯、CRLF 精確復原、外部修改衝突、越界與 symlink、健檢行號與大檔案。
- Web 7 種寬度（1440、1180、980、820、768、560、390）× 4 分頁，共 28 組無水平溢出檢查；另測每種寬度彈窗、章節草稿與 Escape。
- Web 測試涵蓋提示詞保存、工具切換、三類檔案保存與復原、健檢標記、重新整理後保存狀態；無 JavaScript pageerror。
- 桌面 pywebview 使用暫存資料夾，通過版本保存、匯出／復原、真實檔案彈窗儲存與健檢行號。

執行方式：`.venv/bin/python -m pytest -q`；以 `python3 -m http.server 4173 --bind 127.0.0.1` 啟動測試頁，再用可載入 Playwright 的 Node 執行 `scripts/test_ui_revision.cjs`。桌面測試使用 `PYTHONPATH=src .venv/bin/python scripts/smoke_desktop.py`。

完整機器紀錄：[Web](evidence/revision-21/web-tests.json)、[桌面](evidence/desktop-smoke.json)。截圖在 `docs/evidence/revision-21/`，全部使用示範或暫存資料。
