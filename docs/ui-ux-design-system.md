# UI/UX 設計系統

## 2.0 共用 Web UI 補充

- 風格維持溫和淺咖啡、低干擾的本機生產力工具，不採純黑高光的電影式介面。
- 使用 CSS semantic tokens 管理背景、surface、文字、邊框、primary、danger、warning、focus。
- 桌面使用固定側邊欄；820px 以下收斂為 icon rail；560px 以下改為頂部四按鈕導航。
- 所有主要按鈕與輸入至少 44px，高風險寫回提供確認、Diff、disabled 與成功／錯誤回饋。
- 保留可見 label、鍵盤 focus ring、skip link、ARIA live message 與 reduced motion。
- Markdown 表格在 560px 以下改成卡片式 grid，避免檔名被壓成垂直字元。
- 不載入 Google Fonts、CDN 圖示或線上 JavaScript，確保離線啟動。

本文件定義第一版 macOS 桌面 App 的 UI/UX 方向。設計依據包含專案需求、macOS 桌面工具使用情境，以及 `.codex/skills/ui-ux-pro-max/` 的 UI/UX 檢查規則。

## 產品定位

產品類型：個人生產力工具、AI 記憶與提示詞管理工具。

第一版目標不是做華麗行銷頁，而是做一個能長時間使用、資訊清楚、操作穩定的本機桌面 App。

## 設計原則

- 優先清楚，不追求裝飾效果。
- 優先可掃描，不讓使用者在大量文字中迷路。
- 優先本機工具感，不做過度行銷式介面。
- 每個畫面只保留一個主要動作。
- 所有資料修改都要能看出狀態，例如已儲存、未儲存、已產生、轉換失敗。
- 危險操作需要確認或可復原，例如刪除記憶區塊。
- AI 功能要標示是否需要 API Key，避免使用者誤以為所有功能都免費自動執行。

## 視覺方向

採用「安靜、專業、資料管理工具」風格。

避免：

- 過度紫色或 AI 感漸層
- 大面積玻璃擬態
- 行銷網站式 hero layout
- 過多動畫
- 用顏色本身承載重要資訊

建議：

- 淺色模式優先，後續可擴充深色模式。
- 主色使用低飽和藍綠或系統藍，降低長時間使用疲勞。
- 背景以中性灰白為主。
- 操作區與內容區用細邊框、間距與標題層級區分。

## 初始色彩語意

實作時以語意 token 管理，不在元件中散落 raw hex。

```text
background：主背景
surface：內容容器背景
surface-muted：次要區塊背景
border：邊框與分隔線
foreground：主要文字
muted-foreground：次要文字
primary：主要操作
primary-hover：主要操作 hover
success：成功狀態
warning：警告狀態
danger：刪除或危險操作
focus-ring：鍵盤焦點
```

## 字體與排版

- macOS 版優先使用系統字體。
- 中文介面使用系統預設中文字體即可。
- 內文維持可讀，不使用小於 12px 的文字。
- 表格、版本號、token 數量、日期可使用等寬或 tabular number。
- 長文字預設換行，不優先截斷。

## 互動規則

- 可點擊元件必須有 hover / focus / pressed / disabled 狀態。
- 儲存、AI 整理、模板轉換等非同步操作需有 loading 狀態。
- 錯誤訊息要說明原因與下一步，例如「API Key 未設定，請先到設定填入」。
- 刪除記憶需要確認，或提供短暫 undo。
- 表單欄位要有可見 label，不只靠 placeholder。
- 長表單要避免一次攤開所有進階欄位，使用摺疊區或次要區塊。

## 導航架構

第一版主導航採 4 大區：

```text
關於我
專案記憶
提示詞庫
AI 整理器
```

AI 工具模板不作為主導航，而是在「產生提示詞」或「輸出」流程中作為格式選項：

```text
輸出格式：Codex / 通用 ChatGPT / Claude
```

## 可用性檢查

每次完成主要 UI 後，至少檢查：

- 主要動作是否明確。
- 是否有空狀態提示。
- 是否有錯誤狀態。
- 是否有儲存成功或失敗回饋。
- 鍵盤 Tab 順序是否合理。
- 對比是否足夠。
- 長文字是否不會擠破版面。
- 危險操作是否有保護。
